# 要件定義書（ドラフト v0.1）: 赤ちゃん成長記録機能

既存の「マタニティ手帳」PWA を拡張し、妊娠中から乳幼児期まで赤ちゃんの成長を一続きで記録し、家族と共有できるようにする。

- 作成日: 2026-10-03
- ステータス: ドラフト（「8. 未決事項」の決定後に v1.0 とする）

---

## 1. 背景・目的

### 背景
- 現行アプリは「ママの妊娠経過」の支援（週数表示、ママの体重、陣痛タイマーなど）が中心で、**赤ちゃん自身の記録**（エコーの計測値・写真・出生後の成長）を残す場所がない。
- データは端末内（localStorage）だけに保存されるため、**パートナーなど家族と記録を共有できない**。機種変更でデータを失うおそれもある。

### 目的
1. 妊娠中の胎児の計測値から、出生後の身長・体重までを**一本のタイムライン・成長曲線**として残せる。
2. エコー写真や成長の写真、「初めてのできごと」を**アルバムとして振り返れる**。
3. **家族（パートナー、祖父母など）と記録を共有**し、誰でも追加・閲覧できる。

### 成功の目安
- 健診のたびに 1 分以内で計測値と写真を記録できる。
- パートナーが自分の端末で同じ記録をすぐに（数秒〜数十秒で）見られる。

---

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象期間 | 妊娠判明 〜 未就学（**主に 0〜3 歳**。成長曲線の標準値は乳幼児身体発育調査の範囲） |
| 対象ユーザー | 妊婦本人、パートナー、祖父母などの家族 |
| 対応端末 | スマートフォン（iOS Safari / Android Chrome）を主対象。PC ブラウザでも閲覧可 |
| 提供形態 | 現行どおり PWA（GitHub Pages で配信、ホーム画面に追加して利用） |

### 対象外（今回のスコープ外）
- 授乳・おむつ・睡眠などの日々の育児ログ（将来検討）
- 医療機関とのデータ連携、医療的な診断・判定
- 予防接種スケジュール管理（将来検討）
- ネイティブアプリ（App Store / Google Play）での配布

## 3. 利用者と主な利用シーン

| ペルソナ | 主な利用シーン |
| --- | --- |
| ママ（記録の主担当） | 妊婦健診の帰りにエコー写真を撮影してアップロード、推定体重などを入力 |
| パートナー | 通知・タイムラインで記録を見る。出生後は自分も身長・体重や写真を記録 |
| 祖父母（閲覧中心） | 招待リンクから参加し、写真や成長を見てコメント・リアクション |

## 4. 機能要件

優先度: **Must**（初回リリースに必須）/ **Should**（できれば初回）/ **Could**（後回し可）

### 4.1 赤ちゃんプロフィール
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-01 | 赤ちゃんの名前（ニックネーム）、出産予定日を登録できる（既存設定を引き継ぐ） | Must |
| F-02 | 出生後に「生まれた」登録をし、生年月日・性別・出生時の身長/体重/頭囲/胸囲・在胎週数を入力できる | Must |
| F-03 | 出生登録後は表示を「妊娠◯週◯日」から「生後◯ヶ月◯日」（月齢・年齢）に切り替える | Must |
| F-04 | 複数の子ども（きょうだい・双子）を登録し切り替えられる | Should |

### 4.2 胎児の計測記録（妊娠中）
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-10 | 健診日ごとに計測値を記録できる: 推定体重(EFW, g)、児頭大横径(BPD, mm)、大腿骨長(FL, mm)、腹囲(AC, mm)、頭殿長(CRL, mm)、心拍数、メモ | Must |
| F-11 | 記録日の妊娠週数を自動計算して表示する | Must |
| F-12 | 推定体重を**胎児発育曲線（標準値 ±1.5SD）**に重ねたグラフで表示する | Must |
| F-13 | BPD・FL など他の項目もグラフで切り替え表示できる | Should |
| F-14 | 胎動を初めて感じた日などは「できごと」(4.5) として記録する | Must |

### 4.3 出生後の発育記録
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-20 | 測定日ごとに身長(cm)・体重(kg/g)・頭囲(cm)・胸囲(cm)を記録できる | Must |
| F-21 | 母子健康手帳と同じ**乳幼児身体発育曲線（3〜97パーセンタイル）**に重ねて表示する（男女別） | Must |
| F-22 | 胎児期の推定体重と出生後の体重を**一続きのグラフ**で見られる | Should |
| F-23 | カウプ指数など、体格の目安を表示する | Could |

### 4.4 写真・アルバム
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-30 | 写真（エコー写真、マタニティフォト、出生後の写真）をアップロードできる。撮影日・キャプションを付けられる | Must |
| F-31 | 写真は自動で縮小・圧縮して保存する（例: 長辺 2048px、JPEG/WebP） | Must |
| F-32 | 写真を週数・月齢ごとにまとめたアルバム表示 | Must |
| F-33 | 計測記録・できごとに写真を添付できる | Should |
| F-34 | 毎月同じ構図で撮った写真を並べて比較する「月齢フォト」表示 | Could |
| F-35 | 短い動画（エコー動画など）の保存 | Could |

### 4.5 初めてのできごと（マイルストーン）
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-40 | できごとを日付・タイトル・メモ・写真付きで記録できる | Must |
| F-41 | よくあるできごとのテンプレートを用意する（例: 心拍確認、初めての胎動、誕生、首すわり、寝返り、おすわり、はいはい、つかまり立ち、初めての歩行、初めての言葉、初めての歯） | Must |
| F-42 | テンプレートには一般的な時期の目安を表示する（※個人差がある旨を明記） | Should |

### 4.6 タイムライン
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-50 | 計測・写真・できごと・日記を時系列にまとめたタイムラインを表示（妊娠週数/月齢の見出し付き） | Must |
| F-51 | 種類で絞り込みできる | Should |

### 4.7 家族共有
| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-60 | アカウント登録・ログイン（Google ログイン、またはメールリンク） | Must |

| --- | --- | --- |

## 5. 非機能要件

| 区分 | 要件 |
| --- | --- |
| プライバシー・セキュリティ | 写真・記録は家族グループのメンバーのみ閲覧可（アクセス制御をサーバー側ルールで強制）。通信は HTTPS。公開 URL で第三者が閲覧できる状態にしない。 |
| オフライン | オフラインでも閲覧・記録でき、オンライン復帰時に同期する |
| 同期の競合 | 同じ記録を同時編集した場合は「後から保存した方を優先」し、データは消さない |
| パフォーマンス | 初回表示 3 秒以内（4G 回線）。写真一覧はサムネイルを遅延読み込み |
| 容量 | 写真 1 枚あたり 1MB 以下に圧縮。想定: 3 年間で写真 2,000 枚程度 |
| 可用性・バックアップ | クラウド側データは消失しないこと。ユーザー自身もエクスポートで保全できる |
| アクセシビリティ | 文字サイズ変更に追随、色だけに頼らない表示、ダークモード対応（既存踏襲） |
| 医療情報の扱い | 標準曲線との比較は「目安」と明記し、診断的な表現（異常・正常の判定）はしない |
| 運用コスト | 個人・家族利用の規模で**無料枠内**で運用できること |
| 退会 | アカウント削除時にクラウド上のデータ（写真含む）を完全に削除できる |

## 6. データ項目（概要）

```
FamilyGroup   { id, name, members: [{ userId, role: admin|editor|viewer }] }
Child         { id, groupId, name, dueDate, birthDate?, sex?, birth: { lengthCm, weightG, headCm, chestCm, gestWeek } }
FetalRecord   { id, childId, date, efwG?, bpdMm?, flMm?, acMm?, crlMm?, fhrBpm?, note, photoIds[], createdBy, updatedAt }
GrowthRecord  { id, childId, date, heightCm?, weightKg?, headCm?, chestCm?, note, createdBy, updatedAt }
Milestone     { id, childId, date, type(テンプレートID or custom), title, note, photoIds[], createdBy, updatedAt }
Photo         { id, childId, takenAt, caption, storagePath, thumbPath, width, height, createdBy }
```
既存の `weights` / `journal` / `contractions` / `kicks` はママ個人のデータとして保持（共有は任意）。

標準値データ:
- 胎児発育曲線: 日本超音波医学会「超音波胎児計測の標準化と日本人の基準値」
- 乳幼児身体発育曲線: 厚生労働省/こども家庭庁「乳幼児身体発育調査」（最新版の数値を採用、出典をアプリ内に記載）

## 7. 技術方針（案）

| 項目 | 案 | 理由 |
| --- | --- | --- |
| フロントエンド | 既存の素の JS + PWA を継続（ビルドなし） | 既存資産を活かせる。規模的にフレームワーク不要 |
| 認証・DB・写真保存 | **Firebase**（Authentication / Cloud Firestore / Cloud Storage） | 家族共有・リアルタイム同期・オフライン対応が標準機能。無料枠で家族利用は十分。GitHub Pages のまま使える |
| アクセス制御 | Firestore / Storage のセキュリティルールでグループメンバーのみに制限 | サーバーを自前で持たずに安全性を確保 |
| グラフ | 既存と同様に SVG で自前描画 | 依存を増やさない |
| 代替案 | Supabase（PostgreSQL + Storage） | Firebase と同等。SQL で扱いたい場合 |

※ Firebase の Storage 無料枠には条件（課金プラン登録が必要になる場合あり）があるため、実装前に最新条件を確認する。

## 8. 未決事項（要相談）

1. **バックエンド**: Firebase で進めてよいか（Supabase 等の希望はあるか）
2. **ログイン方法**: Google ログインのみでよいか / メールリンク・LINE ログイン等も必要か
3. **複数の子ども（F-04）**: 初回リリースに含めるか
4. **祖父母などの閲覧専用メンバー**: 初回リリースから必要か（パートナーのみなら権限設計を簡略化できる）
5. **ママ個人の記録（体重・日記）**: 家族にも共有したいか
6. **動画（F-35）・コメント（F-65）・通知（F-66）**: 必要度
7. **成長曲線の標準値の出典**: 上記の公的データを使う方針でよいか

## 9. リリース計画（案）

| フェーズ | 内容 |
| --- | --- |
| フェーズ 1（端末内のみ） | 赤ちゃんプロフィール/出生登録、胎児計測＋発育曲線、出生後の身長体重＋発育曲線、できごと、写真（IndexedDB に保存）、タイムライン |
| フェーズ 2（家族共有） | ログイン、家族グループ・招待・権限、クラウド同期、既存データ移行 |
| フェーズ 3（拡張） | 複数の子ども、コメント・通知、月齢フォト、動画、エクスポート強化 |

先に端末内で記録機能を完成させ、その後クラウド同期を載せることで、早い段階から実際に使い始められる。
